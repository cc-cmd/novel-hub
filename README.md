# Novel Hub

本地运行的网文多平台发布管理工具：管理你磁盘上的小说稿件，记录每章在各平台（番茄、起点等）的发布状态，章节改动后自动提示"需更新"，并一键复制符合平台格式的正文。

**核心理念：文件是真相，数据库只是索引。** Novel Hub 不会改动你的稿件目录（仅在你使用内置编辑器保存时写回对应章节文件）；数据库（SQLite）可随时丢弃重建，只会丢失发布状态记录。

## 功能

| 功能 | 说明 |
|---|---|
| 小说库 | 配置一个或多个"小说根目录"，其下每个一级子目录自动识别为一本小说；支持重新扫描、归档 |
| 章节管理 | 扫描 `ChNN-标题.md`，解析 H1 标题、字数；内置编辑器（保存写回磁盘，外部修改时提示冲突）；可配置每本书的章节子目录（如 `改稿/`） |
| 平台与发布矩阵 | 每本书绑定若干平台（预置番茄、起点，可自定义）；章节 × 平台矩阵。已配置的平台（番茄）状态为 未发布 / 已发布 / 需更新，由同步得出、不可手动标记；未配置的平台无状态 |
| 过期提示 | 已配置平台的"需更新"由线上章节与本地稿件比对得出（先比标题与字数，字数不同再比正文），仅换行符、Markdown 写法差异不会误报；同步后本地再改稿会标注"同步后有改动" |
| 平台同步 | 番茄配置认证与作品链接后，重新扫描自动同步 未发布 / 已发布 / 需更新 |
| 发布到番茄 | 一键获取或导入认证；按分卷规则新发章节、覆盖已发布章节，自动跳过审核中等情况，遵守每日字数上限 |
| 一键复制 | 复制「标题+正文」「仅标题」「仅正文」，自动去除 Markdown 标记，输出番茄后台可直接粘贴的格式 |
| 总览看板 | 首页展示每本书已配置平台的各状态章节数、占比条，一眼看出哪些书需要更新 |

## 环境要求

- Node.js 与 npm（开发环境为 Node 26，更低版本未验证）
- macOS / Linux / Windows 均可；`better-sqlite3` 为原生模块，首次 `npm install` 需要能下载预编译包或本机有编译工具链（macOS 需 Xcode Command Line Tools）

## 本地部署

```bash
git clone <repo-url> novel-hub && cd novel-hub
git checkout feat/mvp          # MVP 目前在此分支
npm install
```

开发模式（热更新）：

```bash
npm run dev
```

生产模式（更快、更接近日常使用）：

```bash
npm run build
```

```bash
npm start
```

浏览器打开 <http://127.0.0.1:3000>。服务只监听 `127.0.0.1`，不对局域网开放。

### 配置

| 项 | 默认 | 说明 |
|---|---|---|
| 端口 | 3000 | `PORT=3011 npm start` 或 `npx next dev -H 127.0.0.1 -p 3011` |
| 数据库 | `./data/novel-hub.db` | 环境变量 `NOVEL_HUB_DB=/绝对路径/xxx.db` 可改；首次启动自动建库、迁移、写入预置平台 |

## 使用方式

### 1. 准备稿件目录

```
小说根目录/                 ← 在设置页添加这一层
├── 我的小说A/              ← 每个一级子目录 = 一本小说
│   ├── Ch01-开篇.md
│   ├── Ch02-相遇.md
│   └── ...
└── 我的小说B/
    └── 改稿/               ← 章节在子目录时，在小说详情页设置"章节子目录"
        └── Ch01-xxx.md
```

- 章节文件名格式：`ChNN-标题.md`（`Ch` 不区分大小写，`NN` 为序号）。不符合的文件会列在"问题文件"里，不会被当作章节。
- 章节文件第一行建议写 H1，两种写法均可：
  - `# 第1章 标题`
  - `# 《书名》· 第1章 · 标题`
  - 章号可为阿拉伯数字或中文数字。H1 缺失或章号与文件名不符时章节仍会入库，并显示警告。
- 平台标题统一输出为 `第N章 标题`（章号取文件名序号，标题取 H1 标题）。

### 2. 添加小说库

1. 打开 **设置** 页，在"小说根目录"填入根目录的**绝对路径**（如 `/Users/me/novels`）并添加。路径不存在、不是目录、无读权限会给出明确提示。
2. 回到首页（看板），每个子目录即一本小说。之后在磁盘上新建了小说目录，点"重新扫描"即可。

### 3. 绑定平台、查看发布状态

1. 进入小说详情页，在"管理平台"中绑定要发布的平台（预置番茄、起点，也可自定义）。
2. 矩阵中每个单元格对应"某章 × 某平台"。已配置平台（目前仅番茄）的状态由同步得出，不能手动标记；点"需更新"徽标可查看差异原因、复制标题+正文。未配置平台显示"—"，无状态，不计入看板统计。
3. 发布记录不会被删除，旧版本留下的手动记录仍保留在库中。

### 4. 配置番茄同步

1. 在 **设置** 页的番茄行点"配置"，任选一种方式获取认证信息（Cookie 与 X-Secsdk-Csrf-Token），校验通过后才会保存：
   - **一键获取**：弹出一个专用 Chrome 窗口（独立用户目录 `data/chrome-profile/`，不碰日常 Chrome），在其中登录番茄作家后台，自动读取并校验。登录态保留在该目录，过期后再点一次通常免登录。
   - **从文件导入**：填写 fanqie-publish 技能的 `.env.local` 路径（含 `TOMATO_COOKIE`、`TOMATO_CSRF_TOKEN`）。
   - **手动填写**：从浏览器开发者工具复制请求头。
2. 进入小说详情页，绑定番茄并填入作品的章节管理页链接（形如 `https://fanqienovel.com/main/writer/chapter-manage/<书号>&书名?type=1`）。
3. 点"重新扫描"：先扫描本地文件，再拉取番茄线上章节，把每章同步为 未发布 / 已发布 / 需更新。同步只发查询请求，不会修改线上内容或本地稿件；失败（如认证失效）时各章状态保持不变。

> 同步已用真实账号核对过。若提示"返回格式无法识别"，可能是平台接口变更，请反馈。详见 [REQ-07](docs/requirements/REQ-07-platform-sync.md) §12。

### 4.1 发布到番茄

1. 在 **设置** 页番茄行的「发布设置」里确认 AI 标记（`use_ai`，默认 2）和每日新发字数上限（默认 20000）。
2. 在小说详情页「管理平台」的番茄行填写分卷规则，每行 `起始章-结束章 卷名`，如 `1-50 第一卷：崩塌`。平台只有一卷时可以留空。
3. 在「发布到番茄」面板点"查看发布计划"：列出未发布和需更新的章节，有平台章节 ID 的覆盖，其余新发；审核中、平台找不到、分卷缺失等情况会标注原因且不可勾选。
4. 勾选章节，点"发布选中的 N 章"并确认。覆盖会修改读者可见的内容，章节回到审核中，审核期间不能再改。每章间隔 3 秒提交，遇到额度上限或接口错误即停止。
5. 审核时段为 7:00–24:00。审核通过后点"重新扫描"核对线上状态。

规则细节见 [REQ-08](docs/requirements/REQ-08-platform-publish.md)。

### 5. 复制正文去发布

在章节行点"复制 ▾"：

- 主按钮：复制「标题 + 空行 + 正文」
- 下拉：仅标题 / 仅正文（番茄作家后台标题与正文是两个输入框）

复制内容读取自磁盘上的最新版本，已去除加粗、引用、代码、分隔线等 Markdown 标记（`- x` 转为 `· x`）。复制成功会提示字数。

### 6. 改稿后更新

- 在 Novel Hub 内置编辑器或外部编辑器改了章节，该章标题旁会显示"同步后有改动"，但状态徽标不会立即变化。
- 到番茄重新提交后，在详情页点"重新扫描"，状态会自动更新。
- 内置编辑器保存时若发现文件已被外部修改，会提示冲突，不会覆盖你的外部改动；可选择"放弃并重新加载"。

## 状态说明

仅已配置平台有状态，且只有以下三种，由同步得出：

| 状态 | 含义 |
|---|---|
| 未发布 | 线上没有这一章 |
| 已发布 | 线上版本与本地当前版本一致 |
| 需更新 | 线上存在，但标题或正文与本地不一致 |

看板统计满足：已发 + 需更新 + 未发 = 总章数（仅统计已配置平台）。

## 注意事项

- **每次打开首页都会同步整个书库**。书很多、章节很多时（如上百本×上千章）首次载入可能较慢，尚未做大规模实测。
- 转换规则（hash、字数口径）若将来升级，会自动让缓存失效并重新计算，已发布章节可能因此被判为"需更新"。
- 数据备份：只需备份稿件目录和 `data/novel-hub.db`。删除数据库不会影响稿件，只会丢失发布记录与平台认证信息（重新配置后再扫描即可恢复状态）。
- 番茄 Cookie / CSRF Token 以明文保存在本地数据库中，请勿分享该文件。
- 仅限本机使用，无登录、无多用户。
