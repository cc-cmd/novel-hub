# 平台前置须知：番茄小说

来源：用户现有技能 `fanqie-publish`（`/Users/tutuu/go/陈波宁案/.claude/skills/fanqie-publish/`，含 `SKILL.md` 与 `references/platform-facts.md`，均为实测结论）及其 `pipeline.py`。本文只提炼与 Novel Hub 需求相关的事实；Novel Hub MVP 不做自动发布，这些事实用于约束数据模型、状态、复制格式与提示文案。

## 1. 发布生命周期

| 事实 | 对需求的影响 |
|---|---|
| 提交后进入**审核中**（`display_status=5`），通过后为**已发布**（`display_status=1`） | 发布状态不能只有"未发 / 已发"，需要「审核中」（REQ-03、REQ-06） |
| 审核工作时间 **7:00–24:00**；夜间提交停在审核中，次日 7–9 点出结果 | 「审核中」可能持续数小时，不应视为异常 |
| 审核中的章节**不能修改**（`cant_modify_reason=审核中暂不支持修改`） | 审核中状态下本地改稿允许，但应提示"需等审核结束再覆盖" |
| 对已发布章节用**同一 `item_id` 再次提交 = 覆盖**，章节被**打回审核中** | "重新提交（覆盖）"后状态回到「审核中」（REQ-03 F3.15） |
| 覆盖后是否保留原阅读量 / 评论，平台未验证 | 不在 MVP 承诺；在界面提示"覆盖会重新审核" |
| 审核未过或被撤回，技能侧记为"需重传" | MVP 不单设该状态：取消回「未发布」（REQ-03 Q7） |

## 2. 章节标题与正文

| 事实 | 对需求的影响 |
|---|---|
| 平台标题格式：`第N章 标题`；**标题与正文是两个独立字段** | 复制需要拆分：复制标题 / 复制正文 / 复制标题+正文（REQ-05） |
| 标题来源是章节文件**第一行 H1**（`# 第N章 标题` 或 `# 《书名》· 第N章 · 标题`，N 可为中文数字；真实稿件多用后者），不是文件名 | 章节标题以 H1 为准，文件名标题作后备（REQ-02 §4.1） |
| H1 的章号必须等于文件名序号，否则技能直接中止 | 不一致时给出明确警告（REQ-02） |
| 正文发布形态：去 H1；`**【POV】**` → `【POV】`；`---` → 空行；去引用 `>`；去反引号与 `**`；`- x` → `· x`；去代码围栏；折叠连续空行；去末尾空行 | REQ-05 转换规则以此为基准 |
| 平台正文为 HTML，**每段一个 `<p>`**；`& < >` 需转义 | 粘贴纯文本时，空行分段即可（手动流程无需处理 HTML） |
| `use_ai`：1 = 已使用 AI，2 = 其他；该项目统一用 1 | 属自动化细节，MVP 手动发布无需记录；若后续做自动化再纳入 |

## 3. 字数与内容一致性

| 事实 | 对需求的影响 |
|---|---|
| 本地字数 = 发布形态正文去除所有空白后的字符数（`len(re.sub(r"\s","",text))`），**不含标题行**；平台字数应与之相等（差值 0） | REQ-02 字数口径据此确定 |
| 幂等判定使用 `sha1(标题 + "\n" + 发布形态正文)` | REQ-02 / REQ-04 的 content_hash 改为"发布形态 hash"，含标题，忽略纯 Markdown 写法差异 |
| 刚提交时平台 `word_number=0`，约 10 秒后刷新 | 无影响（MVP 不拉取平台数据） |

## 4. 额度与分卷（MVP 仅作提示，不建模）

| 事实 | 处理 |
|---|---|
| 每日提交上限约 **2 万字**（`-1019`），0 点重置；覆盖不计入"今日已提交"统计，但技能按本批累计控制 | 属后续"发布辅助"：可在标记审核中时累计当日字数并软提示（见 REQ-03 Q9），MVP 不做 |
| 平台有**分卷**；作品按章节区间对应卷（如 1–50 第一卷、51–150 第二卷）；**不能同时存在两个空卷** | MVP 不建模分卷；后续可在 `chapter` 增加 `volume` 字段 |
| 作品存在"书不可搜（book_auth_not_safe）"等平台侧可见性问题 | 与 Novel Hub 无关，不处理 |

## 5. 项目目录结构的启示（来自 `陈波宁传`）

```
陈波宁传/
├── 改稿/                 ← 章节文件在这里：Ch01-私信.md、Ch02-冲我来.md …（含 _v1 等子目录，应忽略）
├── 发布包/正文/           ← 原稿的 .txt：Ch001-私信.txt（3 位序号，非 .md）
├── Act1-崩塌/ …           ← 其他创作资料
├── 重构记录表.md / 上传进度表.xlsx / 设定集.md …（非章节文件）
```

| 事实 | 对需求的影响 |
|---|---|
| 章节文件**不在小说根目录**，而在子目录 `改稿/`；根目录下有大量非章节资料 | 每本小说需可配置「章节目录」（REQ-01 F1.11） |
| 同一小说有多版本稿（原稿 .txt / 改稿 .md） | MVP 一本小说只跟踪一个章节目录；通过切换章节目录选择版本（REQ-01 Q5） |
| 序号位数不固定（`Ch01` / `Ch001`） | 解析已兼容多位数（REQ-02 §4.1） |
| 改稿有"定稿"状态（记在 `重构记录表.md`），技能要求定稿后才覆盖线上 | MVP 不跟踪稿件状态；提示文案提醒；后续可加 `chapter.draft_status`（REQ-02 Q8） |
| 现有 `上传进度表.xlsx` 的状态：未上传 / 待审核 / 已发布 / 需重传 / 上传中，含平台章节 ID、时间 | Novel Hub 状态与之映射：未上传→未发布，待审核→审核中，已发布→已发布，需重传→未发布（备注），上传中→不适用 |

## 6. 与自动发布的边界

该技能已具备自动发布能力（需 Cookie + CSRF，无公开 API）。设计文档明确 MVP **不做自动发布**；MVP 之后已由 [REQ-08](REQ-08-platform-publish.md) 实现发布与覆盖。以下为 MVP 阶段的约定：
- Novel Hub 与 `上传进度表.xlsx` 是**两套独立状态**，MVP 不做互通；用户可在 Novel Hub 手动标记，或后续单独做"导入进度表"（建议作为独立需求评估）。
- 状态与哈希口径刻意与技能保持一致（审核中 / 已发布；标题+发布形态正文的哈希），为将来对接留余地。
