## 1. 背景与目标

章节正文只存在于本地 Markdown 文件。平台需要把文件解析成章节列表、统计字数，并提供一个简单编辑器，把修改安全地写回原文件。

**目标**：自动识别 `ChNN-标题.md`，同步到数据库（序号、标题、字数、hash）；在平台内以纯文本方式编辑并写回文件；外部编辑后能自动同步。

核心原则：**文件是真相，数据库是索引**。

## 2. 用户故事

- 作为作者，我想看到一本书的所有章节、序号、标题和字数。
- 作为作者，我想在平台里直接改某一章并保存，不用切换编辑器。
- 作为作者，我用 VS Code / Typora 等外部工具改稿后，希望平台重新扫描就能反映字数变化。
- 作为作者，我想知道哪些文件命名不规范没被识别，以便修正。

## 3. 范围

### 3.1 包含
- 文件名解析、章节入库与同步（新增 / 缺失 / 改动）
- 字数统计与内容 hash 计算
- 章节列表数据（供详情页与看板使用）
- Markdown 纯文本编辑与写回
- 未识别文件提示

### 3.2 不包含
- 富文本 / 所见即所得编辑、Markdown 预览
- 在平台内新建章节、重命名、删除章节文件
- 文件监听（watcher）
- 版本历史 / 撤销历史

## 4. 业务规则与口径

### 4.1 文件命名与解析

**格式**：`ChNN-标题.md`

| 要素 | 规则（假设，待 Q1 确认） |
|---|---|
| 前缀 | `Ch`，大小写不敏感 |
| `NN` | 一位及以上数字（`Ch01`、`Ch1`、`Ch123` 均合法）；解析为整数 `seq`，前导零忽略 |
| 分隔符 | `-`（半角连字符），其后到扩展名前为标题 |
| 标题 | 去首尾空白后非空；允许中文、空格、标点 |
| 扩展名 | `.md`，大小写不敏感 |

示例：

| 文件名 | 结果 |
|---|---|
| `Ch01-重生之初.md` | seq=1，title=`重生之初` |
| `ch12-第十二回 夜行.md` | seq=12，title=`第十二回 夜行` |
| `Ch003-标题.md` | seq=3 |
| `Ch01.md`（无标题） | 未识别（见 Q2） |
| `第一章.md`、`notes.md` | 未识别 |
| `Ch01-标题.txt` | 未识别 |

**文件内 H1 标题**（依据番茄发布技能）：章节文件第一行应为 `# 第N章 标题` 或 `# 《书名》· 第N章 · 标题`（N 为阿拉伯数字或中文数字，如 `第十二章`）。两种写法均解析出章号与标题；平台标题统一输出 `第N章 标题`，其中 N 取文件名序号，标题取 H1 标题。H1 与文件名章号不一致记警告 `h1_mismatch`，无 H1 记 `no_h1`。

- 章节**标题以 H1 为准**（即发布到平台的标题）；文件名中的标题仅在 H1 缺失或无法解析时作后备。两者允许不同。
- H1 中的章号必须等于文件名序号 `seq`；不一致 → 仍以文件名 `seq` 入库，但该章标记警告「H1 章号与文件名不符」并列入问题文件提示（番茄发布工具遇此直接中止，防止发错章）。
- 无 H1 的文件照常入库（`title` 取文件名标题），标记警告「缺少 H1」。
- 文件内 H1 不计入字数，也不进入正文发布形态（见 F2.10 / F2.11、REQ-05）。

**重复序号**：同一小说内两个文件解析出相同 `seq`（如 `Ch01-a.md`、`Ch1-b.md`）违反 `(novel_id, seq)` 唯一。处理：按文件名字典序保留第一个，其余列入"未识别/冲突文件"并说明原因（见 Q3）。

### 4.2 业务规则

1. 章节正文**不入库**，只在文件中。数据库只存元数据。
2. 发布记录依附 `chapter`，因此章节记录永不因文件丢失而删除（F2.4）。
3. 平台内编辑 = 先写文件、后同步；顺序不可颠倒。
4. 外部编辑器的修改，在下次打开页面或"重新扫描"时同步，存在延迟属预期行为。
5. 数据库可随时从文件重建，**但发布记录除外**（发布记录无法从文件还原）。

## 5. 功能需求

### 5.1 同步（`sync`）

| 编号 | 需求 |
|---|---|
| F2.1 | 对单本小说：列出目录下 `.md` 文件（仅一级，不递归），逐个解析文件名。 |
| F2.2 | **新文件**（库中无该 `seq`）→ 新增章节：读取内容，计算 `word_count`、`content_hash`，`file_missing = false`。 |
| F2.3 | **文件改动**（库中有该 `seq`，且内容 hash 与库中不同，或 `file_path`/标题变化）→ 更新 `title`、`file_path`、`word_count`、`content_hash`。 |
| F2.4 | **文件缺失**（库中有，磁盘上无）→ `file_missing = true`；**保留**章节记录与全部发布记录，**不删除**。 |
| F2.5 | **文件恢复**（此前缺失，现又出现）→ `file_missing = false`，并按 F2.3 更新。 |
| F2.6 | **标题变化**（同 `seq` 文件被改名，或 H1 标题被修改）→ 视为同一章，更新 `title` 与 `file_path`；发布记录保持。标题变化会改变内容 hash（F2.11），已发布章节随之显示「需更新」。 |
| F2.7 | 同步以 `(novel_id, seq)` 为章节身份，不以文件路径为身份。 |
| F2.8 | 触发：打开页面、点击"重新扫描"（整库）、平台内保存成功后（单章）。 |
| F2.9 | 同步幂等：磁盘无变化时重复执行，数据库无变更。 |

### 5.2 字数与 hash

| 编号 | 需求 |
|---|---|
| F2.10 | **字数统计口径**（已与番茄发布技能核对）：对**发布形态正文**（去除 H1 标题行及 Markdown 标记，转换规则见 REQ-05 §4.1）统计**非空白字符数**，即去掉所有空白后的字符数（汉字、字母、数字、标点各计 1）。标题不计入。平台字数与此本地字数应相等。 |
| F2.11 | **发布形态 hash**：对「H1 解析出的标题 + `\n` + 发布形态正文」取 SHA-256（hex）；无 H1 时标题取文件名标题。因此换行符差异（`\r\n`/`\n`）、首尾空白、仅 Markdown 写法不同但发布文本相同的改动**不改变** hash，不会造成误报。这是对设计文档「文件内容归一化」的调整，口径与番茄发布技能的幂等判定一致。 |
| F2.12 | 标题、正文文字、标点、行内空格的变化都会改变 hash。转换规则只有一份实现（`lib/publish.ts`），`lib/hash.ts` 调用它；转换规则调整后，既有 hash 失效，已发章节会整体显示「需更新」，需随规则变更一并评估。 |

### 5.3 章节编辑

| 编号 | 需求 |
|---|---|
| F2.13 | 编辑页 `/novels/[id]/chapters/[cid]`：纯 `<textarea>`，加载文件原文（含 Markdown 标记），使用衬线字体 Noto Serif SC，可调整高度。 |
| F2.14 | 点击"保存"：先写回 `.md` 文件；**成功后**再触发该章单章同步，更新 `word_count`、`content_hash`。 |
| F2.15 | 写文件失败 → 显示错误，**不更新数据库**，textarea 内容保留，用户不丢稿。 |
| F2.16 | 写文件应尽量原子（先写临时文件再 rename），避免写一半崩溃导致原文损坏。 |
| F2.17 | 保存时保持原文件的换行符风格（若原文为 `\r\n` 则不强制改成 `\n`）（见 Q5）。 |
| F2.18 | 页面显示"未保存修改"标记；离开页面前若有未保存修改，浏览器提示确认。 |
| F2.19 | 保存后页面显示最新字数，并更新各平台状态（可能从"已发"变为"需更新"，见 REQ-04）。 |
| F2.20 | `file_missing = true` 的章节，详情页不提供编辑入口（标题不可点，无"编辑"）；直接访问链接时，编辑页禁用保存，提示"文件丢失，无法编辑"。 |
| F2.21 | **外部修改冲突检测**：加载编辑页时记录当时 `content_hash`；保存前重新读取磁盘 hash，若与加载时不同，提示"文件已被外部修改"，让用户选择"覆盖"或"放弃/重新加载"（见 Q6，建议实现）。 |

### 5.4 章节列表数据

| 编号 | 需求 |
|---|---|
| F2.22 | 按 `seq` 升序提供章节列表：章号、标题、字数、`file_missing`；用于详情页表格（呈现见 REQ-03）。 |
| F2.23 | 章号缺口（如 1、2、4）不报错、不补位，原样展示；可在列表中用轻提示标注"缺第 3 章"（可选）。 |

### 5.5 未识别文件提示

| 编号 | 需求 |
|---|---|
| F2.24 | 同步时收集目录内无法识别的 `.md` 文件（及重复序号冲突文件），在小说详情页顶部以折叠提示展示：文件名 + 原因。 |
| F2.25 | 非 `.md` 文件（图片、`.txt`、子目录等）静默忽略，不提示（可能是素材）。 |
| F2.26 | 未识别文件**不报错、不阻塞**其他章节的同步。 |

## 6. 页面与交互

原型：章节编辑、小说详情、空状态与错误状态（见 [README「UX 基准」](README.md)）。

**编辑页 `/novels/[id]/chapters/[cid]`**
- 顶部：返回小说的链接、章号 + 标题、章节文件路径；右侧"复制标题+正文"与"保存"。没有改动时"保存"不可用。
- 主体左侧：textarea（F2.13）；底部状态栏左边显示实时字数，右边显示"与文件一致"／"未保存修改"／"已写回文件，字数与状态已更新"。
- 主体右侧：各已绑定平台一张状态卡（内容见 REQ-03 §6）；窄屏时移到正文下方。
- 写回失败：顶部红色提示"保存失败，文件未被修改"并显示报错原文，状态栏保留"未保存修改"，提供"重试保存"。
- 外部修改冲突（F2.21）：黄色提示"文件已被外部修改"，按钮"覆盖磁盘文件""放弃并重新加载"。

**小说详情页 → 问题文件提示**（F2.24）：折叠条标题"N 个文件需要处理，不影响其他章节"，展开后每行为文件名 + 原因：文件名不符合 `ChNN-标题.md`，未入库／序号重复，未入库／H1 章号与文件名不符，已入库／缺少 H1，已入库，标题取自文件名。

**0 章小说**：详情页显示"这本书还没有章节"及"在章节目录中新建 `Ch01-标题.md`，再回到这里重新扫描"。

## 7. 数据

`chapter(id, novel_id, seq, title, file_path, word_count, content_hash, file_missing)`，`(novel_id, seq)` 唯一。

## 8. 异常场景

| 场景 | 期望行为 |
|---|---|
| 小说目录不存在 | 页面提示，保留已有章节记录（`file_missing` 不批量改写，或统一标记丢失——见与 REQ-01 F1.7 的一致处理，建议：全部章节标记 `file_missing`） |
| 文件无读取权限 | 该章标记异常，不中断其他章节同步 |
| 文件为空 | 合法，字数 0，hash 为空串归一化后的 SHA-256 |
| 文件非 UTF-8 | 该章提示"编码不支持"，不更新字数/hash |
| 写回失败（磁盘满/只读/权限） | 提示错误，DB 不变，textarea 内容保留 |
| 保存期间文件被外部修改 | 见 F2.21 |
| 超大文件（> 2 MB） | 仍可读取；编辑页提示可能卡顿（MVP 不做特殊处理） |

## 9. 验收标准

- **AC2.1** **Given** 目录有 `Ch01-开端.md`、`Ch02-发展.md`、`notes.md`，**When** 同步，**Then** 入库 2 章，`notes.md` 出现在未识别提示中，无报错。
- **AC2.2** **Given** 已同步，**When** 外部编辑器修改 `Ch01` 并重新扫描，**Then** 该章 `word_count` 与 `content_hash` 更新。
- **AC2.3** **Given** 仅把 `Ch01` 的换行符由 `LF` 改为 `CRLF` 并重新扫描，**Then** `content_hash` 不变。
- **AC2.4** **Given** 删除 `Ch02` 文件并重新扫描，**Then** 章节仍在，`file_missing = true`，其发布记录保留。
- **AC2.5** **Given** 恢复 `Ch02` 文件，**When** 重新扫描，**Then** `file_missing = false`，发布记录仍在。
- **AC2.6** **Given** 在编辑页修改并保存，**Then** 磁盘文件内容已更新，页面显示新字数。
- **AC2.7** **Given** 文件设为只读后保存，**Then** 显示写入错误，数据库字数/hash 不变，编辑框内容保留。
- **AC2.8** **Given** `Ch01-a.md` 与 `Ch1-b.md` 同时存在，**Then** 仅一个入库，另一个出现在冲突提示。
- **AC2.9** **Given** 磁盘无变化连续扫描两次，**Then** 数据库无任何记录变更。
- **AC2.10** **Given** 编辑页打开后文件被外部修改，**When** 保存，**Then** 提示冲突并让用户选择（若 Q6 采纳）。

## 10. 测试建议

- **单元测试（设计文档指定）**：
  - `fs-scan`：正常命名、大小写、前导零、多位数、无标题、无序号、错误扩展名、重复序号。
  - `hash`：LF/CRLF、首尾空白差异 → 相同；行内空白差异 → 不同。
- **集成/手动**：同步的新增/缺失/恢复/改名路径；写回失败路径（只读文件）。
