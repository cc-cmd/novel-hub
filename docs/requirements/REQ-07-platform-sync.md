## 1. 背景与目标

MVP 的发布状态完全靠手动标记，并依赖"本地改稿 hash 与上次发布 hash 比较"推断需更新。问题有二：

1. 用户配置的平台作品链接只做了 `http(s)://` 校验，既不保证是对应平台的有效链接，也不保证能用用户的认证信息访问该作品，错误要到真正使用时才暴露。
2. 状态与平台真实情况脱节：线上已有的章节、线上被覆盖的章节，都需要用户逐章手动对账。

本次**仅接入番茄小说**。其他平台（起点及自定义平台）暂不接入，保持现状。

**目标**：（1）番茄平台配置时校验链接格式与认证有效性，不通过则明确提示；（2）在小说详情页点击「重新扫描」时，自动拉取番茄线上章节，把每章状态同步为 **未发布 / 已发布 / 需更新** 三种之一。

## 2. 用户故事

- 作为作者，我填错作品链接或认证过期时，想在保存配置时就被明确告知原因，而不是同步时才发现一片未发布。
- 作为作者，我点一次「重新扫描」，就想让本地章节与番茄线上的发布情况自动对齐。
- 作为作者，我想知道哪些章节线上与本地内容不一致，需要覆盖更新。
- 作为作者，我没有配置的平台，不想看到一堆我没维护的状态。

## 3. 范围

### 3.1 包含
- 番茄平台的认证信息配置（设置页）、作品链接格式校验、认证有效性与作品归属校验
- 「重新扫描」触发的番茄章节同步，及三态判定
- 同步失败的分类提示（认证失效 / 链接无效 / 网络或平台异常）
- 已配置平台与未配置平台的状态展示与操作差异

### 3.2 不包含
- 起点及自定义平台的接入（显示"暂不支持自动校验"）
- 自动发布、覆盖线上内容（只读，仅用 GET 接口）
- 自动抓取 / 刷新认证信息（用户手动粘贴，抓取方法见技能文档）
- 分卷建模、额度统计（见 PLATFORM-NOTES-fanqie §4）
- 定时同步（只在手动点击重新扫描时触发）

## 4. 业务规则与口径

### 4.1 领域规则

**番茄作品链接格式**（样例：`https://fanqienovel.com/main/writer/chapter-manage/7670888040847395864&坏人?type=1`，即作家后台"章节管理"页链接）：

- 主机必须是 `fanqienovel.com`（允许 `www.` 前缀），协议 `http`/`https`。
- 路径须匹配 `/main/writer/chapter-manage/<book_id>`，`<book_id>` 为连续数字。其后紧跟的 `&书名`、`?type=1` 等内容忽略。
- 解析出的 `book_id` 是后续一切接口调用的依据；链接中其他部分不参与。

**"已配置"的定义**：对一本小说的某个平台，同时满足下列条件，称该（小说，平台）为**已配置**：

1. 平台为番茄（唯一支持同步的平台）；
2. 平台已保存认证信息（`Cookie` + `X-Secsdk-Csrf-Token`）；
3. 该小说在此平台上绑定了作品链接，且通过格式校验。

否则为**未配置**。"校验通过"不是持久状态，每次保存与每次同步都会重新校验。

**三态判定**（仅对已配置平台；章节 = 本地章节，线上章节按下述规则配对）：

| 线上情况 | 判定 |
|---|---|
| 线上没有该章 | 未发布 |
| 线上有该章，且**标题一致、字数一致** | 已发布 |
| 线上有该章，**标题不一致**（不论字数） | 需更新 |
| 线上有该章，字数不一致，标题一致，**正文比对有差异** | 需更新 |
| 线上有该章，字数不一致，标题一致，**正文比对无差异** | 已发布（字数口径误差） |
| 线上有该章，但处于审核中，无法读取正文 | 已发布（仅比对标题与字数；字数或标题不一致则需更新） |

**配对规则**：线上章节标题形如 `第N章 标题`（N 可为中文数字），按章号 N 与本地 `chapter.seq` 配对。同一章号在线上出现多条时，取最后更新的一条。线上存在而本地不存在的章号不入库，仅在同步结果提示中计数。

**比对口径**（均与 REQ-02 / REQ-04 保持一致，不重复定义）：

- **字数**：线上 `word_number` 与本地 `chapter.word_count`（发布形态正文去空白后的字符数，不含标题）相等。
- **标题**：线上标题去首尾空白，与本地标题"第N章 标题"格式化后的结果比较（本地标题取 H1 解析结果，见 REQ-02 §4.1）。
- **正文**：线上 HTML 正文按 `<p>` 拆段、反转义 `& < >`、去标签后，与本地"发布形态正文"（REQ-05 转换规则）都去除所有空白字符后逐字比较。

### 4.2 业务规则

1. 已配置平台的章节状态**只有** 未发布 / 已发布 / 需更新，由同步结果覆盖，**不可手动标记**。「审核中」「丢失」等 MVP 状态对已配置平台不再展示。
2. 未配置平台的章节**无状态**：矩阵该单元格不显示任何徽标，也不参与看板统计，不提供手动标记入口。
3. 同步**只读**：只调用查询接口，不修改线上任何内容，不修改本地稿件文件。
4. 同步失败（认证失效、网络错误等）时**保持各章原状态不变**，绝不能把失败当成"线上没有"而批量改成未发布。
5. 认证信息是敏感数据：仅存本地数据库，界面只显示掩码，不写入日志，不出现在错误提示、通知文案或页面源码中。
6. 校验与同步使用同一个认证信息；任一环节返回认证失效，都以同样文案提示。

## 5. 功能需求

### 5.1 平台配置与校验

| 编号 | 需求 |
|---|---|
| F7.1 | 设置页的番茄平台增加「认证信息」配置：`Cookie`、`X-Secsdk-Csrf-Token` 两个输入框。保存后只显示掩码（如 `已配置 · 末4位 abcd`），可「更新」与「清除」。其他平台不显示该配置，并标注"暂不支持自动校验"。 |
| F7.2 | 保存认证信息时立即校验有效性：用其请求番茄书列表接口。成功才保存；失败不保存，提示具体原因（见 §8）。 |
| F7.3 | 小说详情页绑定番茄平台、填写或修改作品链接时，先做格式校验（§4.1）。不符合则阻止保存，提示"链接不符合番茄章节管理页格式，示例：https://fanqienovel.com/main/writer/chapter-manage/<书号>…"。 |
| F7.4 | 链接格式通过后，若平台已保存认证信息，再校验作品归属：解析出的 `book_id` 必须在该账号书列表中。不在则阻止保存，提示"该作品不在当前认证账号下"。 |
| F7.5 | 若平台尚未保存认证信息，则允许保存作品链接（格式校验仍生效），但该（小说，平台）为未配置；绑定行提示"未配置认证信息，不会同步状态"，并提供跳转设置页的入口。 |
| F7.6 | 非番茄平台绑定作品链接时，保持 MVP 现有的 `http(s)://` 校验，不做归属校验。 |
| F7.7 | 绑定行展示该（小说，平台）的配置状态：已配置 / 缺认证 / 缺链接；以及最近一次同步时间与结果（成功或失败原因摘要）。 |

### 5.2 重新扫描触发同步

| 编号 | 需求 |
|---|---|
| F7.8 | 小说详情页「重新扫描」：先执行 MVP 既有的本地扫描，再对该小说所有**已配置**平台依次执行同步。 |
| F7.9 | 看板顶部的全局「重新扫描」：对所有未归档小说执行本地扫描，并对其已配置平台同步。同步按小说串行执行，同一账号下请求之间有间隔（见 Q3）。 |
| F7.10 | 同步先通过 `chapter_list` 获取线上章节（遍历分卷，分页取全），对每个本地章节按 §4.1 判定。字数、标题已能得出"已发布"或"标题不一致 → 需更新"时，不再拉取正文。 |
| F7.11 | 仅当"字数不一致且标题一致"时，才通过 `edit_article` 拉取线上正文做细比对。审核中的章节读不到正文（`code=-2014`），按 §4.1 表末行处理。 |
| F7.12 | 同步结果写入发布记录（`publication`）：状态、同步时间、线上章节 ID、线上字数；并写入 `novel_platform` 的最近同步时间与结果。 |
| F7.13 | 同步完成后，提示条在既有的扫描结果后追加同步汇总，如："番茄同步完成：已发布 38、需更新 2、未发布 10；线上多出 1 章本地没有"。 |
| F7.14 | 同步过程中按钮显示进行中状态且不可重复点击（沿用现有 pending 行为）。 |
| F7.15 | 本地扫描失败或小说目录丢失时，不执行同步（避免用空章节列表覆盖状态）。 |

### 5.3 状态展示与手动操作

| 编号 | 需求 |
|---|---|
| F7.16 | 已配置平台列：徽标仅用 ○ 未发布 / ✓ 已发布 / ↻ 需更新 三种（沿用 MVP 视觉）。徽标点击不再提供"标记已发 / 取消发布 / 审核中"等手动操作；悬浮提示"状态由番茄同步，点击重新扫描刷新"。「需更新」可点击，在行下方展开差异原因、本地与线上字数和复制入口（不含"标记已更新"，也不做正文 diff）。 |
| F7.17 | 未配置平台列：单元格显示"—"，无徽标无操作，列头旁提示"未配置，无状态"。 |
| F7.18 | 矩阵筛选"只看未发布 / 需更新"仅作用于已配置平台列。 |
| F7.19 | 看板的各状态章节数、占比条：只统计已配置平台；未配置平台不计入。口径变化见 §7。 |

### 5.4 体验要求

| 编号 | 需求 |
|---|---|
| F7.20 | **进度**：详情页重新扫描按钮依次显示"扫描本地文件…""同步番茄…"；看板全局重新扫描显示"同步中 X/Y…"（Y 为要同步的小说数）。 |
| F7.21 | **结果分条**：同步失败时，本地扫描结果保留，错误单独一条；认证失效的错误带「去设置」。全局扫描的单本失败只在提示条汇总本数，原因标在该卡片上。 |
| F7.22 | **同步后有改动**：章节文件修改时间晚于该章 `publication.synced_at` 时，标题旁显示"同步后有改动"，并计入新鲜度条。文件丢失或从未同步的章节不算。这是提示，不改变状态。 |
| F7.23 | **未配置清单**：番茄已绑定但未配置时，详情页显示"还差一步开启番茄同步"清单和对应入口，并隐藏筛选。 |
| F7.24 | **新鲜度条**：番茄已配置时，详情页表格上方固定显示状态的新鲜程度（文案见 §6）；1 分钟内同步成功且无改动时算"刚同步"。看板在任一小说认证失效时显示常驻错误条。 |
| F7.25 | **需更新操作条**：内容见 §6。差异原因只用已入库字段推断：线上字数等于本地字数时为"字数相同，标题不同"，否则为"字数不同，内容不一致"；没有线上字数时为"线上内容不一致"。 |
| F7.26 | **文件丢失**：标签显示在标题旁，平台徽标保持上次同步结果，复制和编辑不可用。 |
| F7.27 | **编辑页**：已配置平台的卡片不提供状态操作，保留发布时间与章节链接；保存改动后徽标不变，提示需重新扫描。未配置平台的卡片显示"—"。 |
| F7.28 | **看板卡片**：内容见 §6，包括每个已配置平台的最近同步时间或失败原因、未配置平台的汇总说明、目录丢失时"状态保持上次同步结果"。 |
| F7.29 | **认证面板**：清除前内联确认；保存或清除认证后清掉该平台所有小说的 `last_sync_error`；各处「去设置」都定位到设置页番茄行。 |
| F7.30 | **链接即时提示**：输入作品链接时实时提示获取方法、格式错误或解析出的书号；这只是提示，保存时仍按 F7.3、F7.4 校验。 |

## 6. 页面与交互

原型：[Novel Hub UI 设计](https://claude.ai/artifact/5qTYWHaaX2M4goaaw3EYSY) 的「REQ-07 平台同步」页。未提及的部分沿用 MVP 版本。

**设置页（平台区）**
- 番茄行常驻"认证信息"面板，行尾标签：可同步 / 缺认证 / 认证已失效。
- 未编辑时显示掩码（`已配置 · 末4位 abcd`）与「更新」「清除」；未配置时显示「配置」。
- 编辑时显示获取方法："在已登录的番茄作家后台，从浏览器开发者工具中复制请求头。只保存在本机数据库，保存后不再显示原文。"，以及 `Cookie`（多行）、`X-Secsdk-Csrf-Token`（密码框）、「保存并校验」「取消」。校验期间按钮为"校验中…"，错误显示在输入框下方，保存后清空输入。
- 「清除」先内联确认："清除后，所有小说的番茄列显示"—"，看板不再统计。已有记录保留，重新配置并扫描后恢复。"
- 保存成功提示："✓ 认证信息已校验并保存。回到小说详情页点"重新扫描"即可同步。"
- 认证失效时面板显示"认证已失效，番茄同步已暂停。请重新获取后点"更新"。"；各处「去设置」都定位到番茄行。
- 起点及自定义平台显示"暂不支持自动校验"。

**小说详情页**
- **管理平台 → 番茄绑定行**：行内显示配置标签（已配置 / 缺认证 / 缺链接）与"最近同步：时间 · 成功 / 失败原因"；链接输入框下方实时显示提示（空：获取方法；格式错：应有格式；格式对：`✓ 格式正确，书号 N`）。「保存并校验」的错误就近显示。缺认证时提示"未配置认证信息，不会同步状态。去设置"。
- **未配置引导**：番茄未配置时，表格上方显示清单"还差一步开启番茄同步"（✓/○ 番茄认证信息、本书的作品链接，附入口）；隐藏筛选。
- **新鲜度条**（已配置时固定在表格上方）：见下表。
- **矩阵**：已配置列显示三态徽标；未配置列整列显示"—"并置灰，列头为"起点 · 未配置"。已发、未发徽标不可点击。
- **需更新操作条**：点击徽标在行下方展开差异原因（规则见 F7.25）、"本地 N 字 · 线上 N 字"、「复制标题+正文」「打开番茄后台」，并提示"在番茄覆盖后点"重新扫描"，状态会自动更新。覆盖会重新审核，请确认已定稿。"
- **文件丢失**：标签移到标题旁，平台徽标保持上次同步结果；复制、编辑不可用。
- **同步后改动**：上次同步后本地改过的章节，标题旁显示"同步后有改动"。
- **重新扫描**：详情页按钮为主按钮，文案依次为"扫描本地文件…""同步番茄…"，期间禁用。结果分两条：本地扫描结果 + 同步结果；同步失败时本地结果保留，错误条单独显示，认证失效带「去设置」。

| 新鲜度条场景 | 文案 |
|---|---|
| 刚同步成功 | 番茄状态已是最新 — 刚刚同步。状态由番茄同步，不能手动修改。 |
| 有过同步 | 最近同步：{时间} — N 章在同步后有本地改动，重新扫描后状态才会更新。（无改动时省略后半句） |
| 上次失败 | 上次同步失败 — 下方仍是 {时间} 的状态，可能已过期。 |
| 从未同步 | 尚未同步 — 点"重新扫描"获取番茄线上状态。 |

**章节编辑页**：番茄卡显示徽标、"状态由番茄同步 · 最近同步：{时间}"、同步时线上字数、发布时间、章节链接和「保存发布信息」，没有状态操作按钮。保存改动后显示"本地已改动，这里的状态要等重新扫描才更新。去重新扫描"，徽标不变（替代 REQ-02 F2.19 的即时刷新）。未配置平台的卡片显示"—"和"未配置，无状态。暂不支持自动校验。"

**看板**
- 卡片按 F7.19 统计：只显示已配置平台的三段比例条和"已发 / 需更新 / 未发"，下方一行"最近同步：{时间}"或"同步失败：{原因}，状态未改动"。其他平台收敛为一行"起点 未配置，不计入统计"。
- 没有已配置平台：显示"未配置同步。去配置"，不显示比例条；未绑定平台仍为"未绑定平台。去绑定"。
- 目录丢失：标签"目录丢失，未同步"，计数保持上次结果，并注明"状态保持上次同步结果"。
- 全局重新扫描：按钮显示"同步中 X/Y…"；结果汇总如"本地扫描完成：新增 0 本、更新 2 章。番茄同步：1 本成功，1 本失败"，单本失败只标在该卡片上。认证失效影响全部小说，用顶部错误条"番茄认证已失效，所有小说暂停同步，各章状态未改动。去设置"。

## 7. 数据

对 MVP 数据模型的变更（**新增列，非破坏性迁移**，不删除任何既有数据）：

| 表 | 变更 | 说明 |
|---|---|---|
| `platform` | 新增 `cookie`（text，可空）、`csrf_token`（text，可空） | 仅番茄使用；明文存本地库（见 Q2） |
| `novel_platform` | 新增 `book_id`（text，可空）、`last_synced_at`（integer，可空）、`last_sync_error`（text，可空） | `book_id` 由作品链接解析得出，保存链接时写入 |
| `publication` | 新增 `platform_item_id`（text，可空）、`platform_word_count`（integer，可空）、`synced_at`（integer，可空） | 记录线上章节 ID 与字数，便于后续覆盖发布与核对 |
| `publication.status` | 已配置平台只写入 `unpublished` / `published` / `stale`；`stale` 在此类平台上**入库**（MVP 中"需更新"是计算态） | 与 MVP「需更新不入库」规则的差异，见下 |

**与既有需求的差异（需同步修订对应文档）**：

- REQ-03 §4.1：已配置平台的状态不再手动维护，且不含 `pending_review`。未配置平台**不再有状态**（MVP 为 3 态手动），手动标记入口移除。
- REQ-04：已配置平台的"需更新"由线上比对判定，不再使用 `published_hash` 与本地 hash 比较；未配置平台无状态故不参与。
- REQ-06：看板状态计数、占比条仅统计已配置平台。
- REQ-02 F2.19：保存后不再即时刷新已配置平台的状态，改为提示需重新扫描（§6）。

迁移期间，已存在的 MVP 手动状态记录**保留不删除**，但对已配置平台首次同步后被覆盖；对未配置平台不再展示（数据仍在库中，不破坏 REQ-03 §4.3 的"发布记录不丢"原则）。

## 8. 异常场景

| 场景 | 期望行为 |
|---|---|
| 链接不是 `fanqienovel.com` 或路径不是 `chapter-manage` | 阻止保存，提示格式错误并给出示例 |
| 链接格式对，但 `book_id` 不在账号书列表 | 阻止保存，提示"该作品不在当前认证账号下" |
| 认证信息缺失 | 允许保存链接，但标记"未配置认证信息，不会同步状态" |
| 保存认证信息时接口返回 `code=-1` / 未授权 | 不保存，提示"认证无效或已过期，请重新获取 Cookie 与 CSRF Token" |
| 同步时认证失效 | 本次同步中止，各章状态不变，提示条与绑定行显示"认证已失效"，带「去设置」入口 |
| 网络错误 / 超时 / 平台 5xx | 同步中止，状态不变，提示"番茄暂时无法访问，稍后重试"；本地扫描结果不受影响 |
| 平台返回非预期结构（接口变化） | 同步中止，状态不变，提示"番茄返回格式无法识别，接口可能已变更"，错误细节只写本地日志（不含认证信息） |
| 某章 `edit_article` 失败（非 `-2014`） | 该章保持原状态，同步结果计入"N 章无法比对"，其他章继续 |
| 线上章号重复 / 线上有本地没有的章 | 重复取最新；多出的章不入库，仅计数提示 |
| 本地章节 `fileMissing` | 不参与判定，保持原状态（沿用 MVP 保护发布记录原则） |
| 同步中途页面被关闭 / 请求被中断 | 已写入的结果保留，未处理的章节保持原状态，下次扫描重新判定 |
| 认证信息出现在错误提示中 | 不允许；所有错误文案须经过脱敏 |

## 9. 验收标准

- **AC7.1**（F7.3）Given 填写 `https://fanqienovel.com/main/writer/chapter-manage/7670888040847395864&坏人?type=1`，When 保存，Then 通过格式校验并解析出 `book_id = 7670888040847395864`。
- **AC7.2**（F7.3）Given 填写 `https://example.com/book/123` 或 `https://fanqienovel.com/page/123`，When 保存番茄作品链接，Then 阻止保存并提示格式错误。
- **AC7.3**（F7.2）Given 填入无效的 Cookie，When 点击「保存并校验」，Then 不保存，并提示认证无效或已过期。
- **AC7.4**（F7.4）Given 认证有效但 `book_id` 不在该账号书列表，When 保存作品链接，Then 阻止保存并提示作品不在当前账号下。
- **AC7.5**（F7.8, F7.10）Given 已配置番茄，线上第 1–3 章标题与字数均与本地一致、第 4 章线上不存在，When 点击重新扫描，Then 第 1–3 章为已发布，第 4 章为未发布。
- **AC7.6**（F7.10）Given 线上第 5 章标题与本地不一致，When 重新扫描，Then 该章状态为需更新，且未拉取其正文。
- **AC7.7**（F7.11）Given 线上第 6 章字数与本地不同、标题一致、正文确有差异，When 重新扫描，Then 状态为需更新。
- **AC7.8**（F7.11）Given 线上第 7 章字数与本地不同但正文去空白后完全一致，When 重新扫描，Then 状态为已发布。
- **AC7.9**（F7.11）Given 线上第 8 章处于审核中、读不到正文，字数与标题均一致，When 重新扫描，Then 状态为已发布。
- **AC7.10**（§4.2-4）Given 认证已过期，When 重新扫描，Then 各章状态保持不变，提示条显示认证失效，且本地扫描结果正常展示。
- **AC7.11**（F7.16, §4.2-1）Given 已配置平台，When 查看矩阵，Then 徽标只会是 未发布 / 已发布 / 需更新，且无手动标记入口。
- **AC7.12**（F7.17, §4.2-2）Given 未配置平台（无认证信息或无有效链接），When 查看矩阵，Then 该列显示"—"，无徽标、无手动操作，且不计入看板统计。
- **AC7.13**（§4.2-3）Given 任意同步，Then 仅发出 GET 查询请求，本地稿件文件与线上内容均未被修改。
- **AC7.14**（§4.2-5）Given 保存了认证信息，When 查看设置页、通知、日志，Then 均不出现 Cookie 与 CSRF Token 原文。
- **AC7.15**（F7.9）Given 两本小说都已配置，When 在看板点击全局重新扫描，Then 依次同步两本，其中一本失败不影响另一本。
- **AC7.16**（F7.20）Given 已配置番茄，When 在详情页点击重新扫描，Then 按钮依次显示"扫描本地文件…""同步番茄…"，期间不可点击；看板全局扫描显示"同步中 X/Y…"。
- **AC7.17**（F7.21）Given 认证已过期，When 在详情页重新扫描，Then 本地扫描结果和错误条分开显示，错误条带「去设置」，点击后定位到设置页番茄行。
- **AC7.18**（F7.22）Given 某章已同步，When 本地改稿并保存，Then 该章标题旁显示"同步后有改动"，徽标不变，新鲜度条计入该章；重新扫描后提示消失。
- **AC7.19**（F7.23）Given 番茄已绑定但缺认证或缺链接，When 打开详情页，Then 显示未配置清单，番茄列为"—"，筛选隐藏。
- **AC7.20**（F7.24）Given 上次同步失败，When 打开详情页，Then 新鲜度条显示"上次同步失败"和上次成功时间。
- **AC7.21**（F7.25）Given 第 7 章线上字数与本地相同但判为需更新，When 点击徽标，Then 显示"字数相同，标题不同"和两边字数，不提供"标记已更新"。
- **AC7.22**（F7.16）Given 已配置平台，When 点击"已发"或"未发"徽标，Then 没有任何操作。
- **AC7.23**（F7.29）Given 设置页显示"认证已失效"，When 保存新的有效认证，Then 标签变为"可同步"，看板常驻错误条消失。

## 10. 测试建议

**单元测试**（平台 HTTP 客户端做成可注入接口，用夹具模拟响应）：

- 链接解析：样例链接、含 `&书名` / `?type=1`、带 `www.`、非数字书号、其他主机、其他路径。
- 三态判定表的每一行（含审核中、重复章号、中文数字章号）。
- 正文比对：HTML 转纯文本（`<p>` 拆段、实体反转义）与本地发布形态正文的归一化比较。
- 失败路径：认证失效、网络错误、结构异常，断言状态未被改写。
- 脱敏：错误文案不含认证信息。
- 数据迁移：旧库升级后既有发布记录保留。

**集成测试**：重新扫描 action 先本地后同步的编排；同步失败不影响本地扫描结果。

**手动验证项**：

- 用真实的番茄账号和样例链接，保存配置并点击重新扫描，核对三态与作家后台一致。
- 故意改一个字、改标题、删一章，分别验证判定。
- 使认证过期（清除 Cookie），验证提示与状态保持。
- 夜间审核时段，验证审核中章节的处理。
