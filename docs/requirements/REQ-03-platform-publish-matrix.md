## 1. 背景与目标

同一本小说常同时发布到多个平台（番茄、起点等）。作者需要一眼看清"哪一章发到了哪个平台"。平台**不做自动发布**，发布状态由用户手动标记。

**目标**：管理平台列表；让每本小说绑定若干平台；以"章节 × 平台"矩阵记录并展示每章在每个平台的发布状态，支持手动切换与筛选。

## 2. 用户故事

- 作为作者，我想预置好番茄、起点，也能添加其他平台（如晋江、七猫）。
- 作为作者，我想只给这本书绑定它真正在发的平台，避免矩阵里出现无关列。
- 作为作者，我想记录每本书在各平台的作品主页链接，方便跳转。
- 作为作者，我发完一章后，想一键标记"已发"，必要时能取消。
- 作为作者，我想只看"没发的章节"，快速知道下一步该发什么。

## 3. 范围

### 3.1 包含
- 平台管理：预置 + 自定义新增（设置页）
- 小说 ↔ 平台绑定与解绑，作品主页链接
- 发布记录：章节 × 平台的状态（未发 / 已发）、发布时间、章节链接
- 详情页矩阵展示、徽标切换、筛选

### 3.2 不包含
- 自动发布、平台数据抓取、平台登录
- 平台"定时发布"等其他中间状态（MVP 仅 未发布 / 审核中 / 已发布 三种手动状态）
- 批量标记（见 Q5，建议后续）

## 4. 业务规则与口径

1. `status` 存三种手动值：`unpublished`（未发布）/ `pending_review`（审核中，已提交待平台审核）/ `published`（已发布）；"需更新"是计算态，不入库（REQ-04）。这是对设计文档「仅两种手动值」的调整：番茄等平台有审核环节，覆盖已发布章节会重新进入审核。
2. `(chapter_id, platform_id)` 唯一，一章在一个平台至多一条发布记录。
3. 发布记录不可从文件重建，是库中最需保护的数据：任何同步、解绑、文件丢失都**不得删除**它。
4. 状态变更只改库，不触碰文件，不调用任何外部平台。
5. 未绑定的平台，其发布记录不参与看板统计（REQ-06）。

## 5. 功能需求

### 5.1 平台管理（设置页）

| 编号 | 需求 |
|---|---|
| F3.1 | 首次启动自动写入预置平台：**番茄**、**起点**，`builtin = true`。 |
| F3.2 | 用户可新增自定义平台：名称必填，去首尾空白，长度 1–20；名称不可与已有平台重复（忽略大小写和首尾空白）。 |
| F3.3 | 预置平台**不可删除**，不可改名。自定义平台可改名。 |
| F3.4 | 自定义平台可删除，**仅当**没有任何小说绑定、也没有任何发布记录引用它时；否则拒绝并说明被引用情况（见 Q1）。 |

### 5.2 小说绑定平台

| 编号 | 需求 |
|---|---|
| F3.5 | 在小说详情页（或其设置区）勾选/取消勾选平台，生成/移除 `novel_platform`。 |
| F3.6 | 每个绑定可填写 `book_url`（作品主页链接），可空；填写时校验 `http(s)://` 开头；有值时矩阵列头可点击跳转（新窗口打开）。 |
| F3.7 | 矩阵**只显示已绑定**平台的列。未绑定任何平台时显示引导："请先绑定发布平台"。 |
| F3.8 | **解绑**：移除 `novel_platform`，该列从矩阵隐藏，但对应的 `publication` 记录**保留**（避免误操作丢失）；重新绑定后记录恢复可见。有发布记录时，取消勾选后先在该平台行下方内联确认："已有 N 条发布记录将被隐藏，重新绑定后恢复。"，按钮"确认解绑""取消"。 |

### 5.3 发布矩阵（小说详情页）

| 编号 | 需求 |
|---|---|
| F3.9 | 表格：行 = 章节（按 `seq` 升序），列 = 章号、标题、字数、各绑定平台状态徽标、操作（复制正文、编辑）。 |
| F3.10 | 徽标状态共 5 种展示（其中"需更新"为计算所得，详见 REQ-04）：**未发**（○ 白底灰边）、**审核中**（◷ 浅蓝）、**已发**（✓ 实心蓝）、**需更新**（↻ 橙）、**文件丢失**（! 红色虚线边）。 |
| F3.11 | 没有 `publication` 记录的章节×平台，等同 `unpublished`；记录**惰性创建**——首次标记时才写入。 |
| F3.12 | 点击徽标，在该章节行下方展开操作条（再次点击收起）：「未发」→「标记审核中」「标记已发布」；「审核中」→「标记已发布（审核通过）」「取消」（回未发，如被驳回）；「已发 / 需更新」→「取消已发」「重新提交（覆盖，进入审核中）」「标记已发布（更新为当前版本）」「编辑发布信息」，并提示"覆盖会重新审核，请确认已定稿。" |
| F3.13 | **标记审核中 / 标记已发布**（从未发布出发）：写入对应 `status`、`published_at = 当前时间`、`published_hash = 当前 chapter.content_hash`。审核中 → 已发布（审核通过）只改 `status`，**不改** `published_hash` 与 `published_at`（内容仍是提交时的版本）。 |
| F3.14 | **取消 / 取消已发**：`status = unpublished`，清空 `published_at`、`published_hash`（保留 `platform_url`）。提示条提供"撤销"，恢复原 `status`、`published_at`、`published_hash`，防止误触丢失记录。 |
| F3.15 | **重新提交（覆盖）**：用于"需更新"后用户已把新版本覆盖提交到平台：`status = pending_review`，刷新 `published_at` 与 `published_hash`。平台无审核环节或用户已确认通过时，可用「标记已发布」直接置为已发布并刷新两者。 |
| F3.16 | 可选填 `platform_url`（该章在平台上的链接），在编辑页平台状态卡中编辑，操作条「编辑发布信息」跳转至此；有值时操作条提供"打开链接"（新窗口）。 |
| F3.17 | 章节 `file_missing = true`：徽标显示"文件丢失"，有发布记录时操作条仅提供"取消已发"并提示"文件丢失的章节没有可对照的内容，不能标记已发。"；无发布记录时徽标不可点击。 |
| F3.18 | 切换状态为即时操作（乐观更新 + 失败回滚并提示）。 |

### 5.4 筛选

| 编号 | 需求 |
|---|---|
| F3.19 | 工具栏筛选：全部 / 只看需更新 / 只看未发布。 |
| F3.20 | 筛选语义（多平台时）：**任一已绑定平台**满足条件，该章即出现；可再选平台下拉限定到某一平台（见 Q2）。 |
| F3.21 | 筛选状态可保存在 URL 查询参数（如 `?filter=stale&platform=3`），刷新后保留、可分享。 |
| F3.22 | 筛选后显示命中数量："显示 12 / 共 80 章"。 |
| F3.23 | **审核中提示**：徽标悬浮提示"平台审核中，暂不能修改该章（番茄审核时段 7:00–24:00）"。审核中状态下本地仍可改稿；改稿后该徽标显示「需更新」（见 REQ-04），提示"待审核结束后再覆盖"。 |

## 6. 页面与交互

原型：设置、小说详情、章节编辑、空状态与错误状态（见 [README「UX 基准」](README.md)）。

**设置页（平台区）**
- 平台列表：名称、预置标识、"被 N 本小说绑定"；"新增平台"输入框 +"添加"。
- 自定义平台行有"重命名"（就地变为输入框 +"保存"）和"删除"。
- 错误文案："平台已存在"／"平台名称长度应为 1–20 个字"；删除被引用平台时显示"无法删除：{平台}被 N 本小说绑定，并有 M 条发布记录。请保留该平台。"

**小说详情页 `/novels/[id]`**
- 顶部：返回看板、书名、章数/字数/丢失章数、目录路径、章节目录（REQ-01 §6）；右侧"重新扫描""管理平台"。
- "管理平台"在页内展开面板：每个平台一行，勾选框 + `book_url` 输入；解绑确认见 F3.8。
- 问题文件折叠提示（REQ-02 §6）。
- 工具栏：分段筛选"全部 N／只看需更新 N／只看未发布 N"（数字实时）、平台下拉，右侧"显示 X / 共 Y 章"。
- 矩阵表格如 §5.3：有 `book_url` 的列头带 ↗ 可跳转；操作列"复制 ▾""编辑"（REQ-05 §6）。文件丢失的章节字数显示"—"。
- 未绑定任何平台：表格位置显示"请先绑定发布平台"和"管理平台"按钮。
- 筛选为空：需更新为"所有已发章节都是最新的"，未发布为"没有未发布的章节"。

**章节编辑页 → 平台状态卡**（每个已绑定平台一张）
- 平台名 + 徽标 + 状态说明；发布时间（非未发时显示，可修改，见 Q6）；章节链接 `platform_url`。
- 操作按钮与详情页操作条一致，按 F3.12 随状态变化；基于已保存内容计算，保存后立即刷新。

## 7. 数据

- `platform(id, name, builtin)`
- `novel_platform(novel_id, platform_id, book_url)`，`(novel_id, platform_id)` 唯一
- `publication(chapter_id, platform_id, status[unpublished|pending_review|published], published_at, platform_url, published_hash)`，`(chapter_id, platform_id)` 唯一

## 8. 异常场景

| 场景 | 期望行为 |
|---|---|
| 新增重名平台 | 拒绝，提示"平台已存在" |
| `book_url` 非法 | 拒绝，提示格式错误 |
| 切换状态写库失败 | 回滚徽标，提示条报错 |
| 删除仍被引用的平台 | 拒绝并说明引用 |
| 对 `file_missing` 章节标记已发 | 禁止，提示原因 |
| 并发（两个标签页）同时切换 | 以后写入为准；刷新后以库为准 |

## 9. 验收标准

- **AC3.1** **Given** 全新安装，**Then** 设置页平台列表含番茄、起点，且无法删除/改名。
- **AC3.2** **Given** 新增平台"晋江"，**Then** 它出现在可绑定列表；重复新增被拒。
- **AC3.3** **Given** 小说只绑定番茄，**Then** 矩阵只有番茄一列。
- **AC3.4** **Given** 某章在番茄"未发布"，**When** 点击徽标并选择"标记已发布"，**Then** 徽标变为实心蓝"已发"，库中 `published_hash` = 该章当前 `content_hash`，`published_at` 有值。
- **AC3.5** **Given** 某章"已发布"，**When** 取消已发，**Then** 回到灰边"未发"，`published_at`/`published_hash` 清空；点击提示条"撤销"后恢复原状态与两个字段。
- **AC3.6** **Given** 某小说解绑番茄后重新绑定，**Then** 此前的番茄发布记录仍在且徽标状态不变。
- **AC3.7** **Given** 选择"只看未发布"，**Then** 仅显示至少一个绑定平台未发布的章节，并显示命中数。
- **AC3.8** **Given** `?filter=stale` 的 URL，**When** 刷新，**Then** 筛选保持。
- **AC3.9** **Given** 章节文件丢失，**Then** 徽标显示"文件丢失"，不可标记已发，可取消已发，发布记录未删除。
- **AC3.10** **Given** 小说未绑定任何平台，**Then** 页面显示绑定引导而非空矩阵。

## 10. 测试建议

- 单元：筛选谓词（未发布/需更新）、状态转换（标记/取消/重新提交）对字段的影响。
- 手动：全部验收场景；多标签页并发切换。

## 11. 待确认问题

| # | 问题 | 当前假设 |
|---|---|---|
| Q1 | 自定义平台删除条件 | 无绑定且无发布记录才可删。 |
| Q2 | 多平台下的筛选语义 | "任一平台命中"，并提供平台下拉缩小范围。 |
| Q3 | 平台列表的排序 | 按创建顺序（预置在前）；不支持拖拽排序。 |
| Q4 | 章节数很多（500+）是否分页 | MVP 不分页，表格虚拟滚动或直接渲染；超 1000 章再优化。 |
| Q5 | 批量标记（如"全选 → 标记已发"） | MVP 不做，作为后续优化；但开发时应考虑接口不排斥批量。 |
| Q6 | 标记"已发"的 `published_at` 是否允许用户手动指定（补录历史发布日期） | 默认取当前时间；编辑页平台状态卡中允许修改。 |
| Q7 | 审核被驳回 / 撤回（番茄技能记为"需重传"）如何记录 | 点「取消」回到未发布；MVP 不单设状态，也不记录备注（数据模型无备注字段，原型无此输入）。 |
| Q8 | 是否增加 `platform_item_id`（平台章节 ID，覆盖发布依赖它） | MVP 不加，手动流程不需要；未来对接自动发布或导入 `上传进度表.xlsx` 时再加。 |
| Q9 | 每日提交字数额度（番茄约 2 万字/天）软提示 | MVP 不做；列为后续「发布辅助」，见平台前置须知 §4。 |
