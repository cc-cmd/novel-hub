# REQ-NN 需求名称

| 项 | 内容 |
|---|---|
| 名称 | 需求名称 |
| 编号 | REQ-NN |
| 来源 | 产品设计文档章节引用 |
| 优先级 | P0 / P1 / P2 |
| 状态 | 草案（待评审）/ 已评审 / 已实现 |
| 依赖 | 前置需求编号 |
| 被依赖 | 后续需求编号 |

## 1. 背景与目标
一段背景 + 加粗的"目标"一句话。

## 2. 用户故事
"作为…，我想…，这样…"，3–5 条。

## 3. 范围
### 3.1 包含
### 3.2 不包含

## 4. 业务规则与口径
### 4.1 领域规则（命名/判定/格式/统计口径等，无则省略，直接写规则列表）
### 4.2 业务规则（编号列表，不可违反的约束）

## 5. 功能需求
按子主题分 ### 5.x；每条形如 `F{NN}.{n}`（NN 为需求序号），表格或列表，一条只描述一个可验证行为。

## 6. 页面与交互
涉及页面、区域、按钮、反馈（toast/提示）。

## 7. 数据
涉及的表/字段；是否新增；与设计文档的差异需显式标注。

## 8. 异常场景
表格：场景 | 期望行为。

## 9. 验收标准
Given / When / Then，编号 `AC{NN}.{n}`，每条可追溯到功能需求。

## 10. 测试建议
单元测试范围（对应设计文档 §7）+ 手动验证项。

## 11. 待确认问题
表格：# | 问题 | 当前假设。编号 `Q{n}`，需求内唯一。
