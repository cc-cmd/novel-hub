## 1. 背景与目标

REQ-07 只读同步番茄状态，发布仍需手动复制粘贴。技能 `fanqie-publish` 已能通过作家后台接口发布与覆盖章节。**目标：让 Novel Hub 录入与技能相同的信息，在网站内完成认证获取、发布新章节、覆盖已发布章节。**

## 2. 用户故事

- 作为作者，我想点一下就获取番茄认证，不用打开开发者工具复制请求头。
- 作为已在用技能的作者，我想直接导入技能的 `.env.local`，不用重新登录。
- 作为作者，我想看到哪些章节要新发、哪些要覆盖、哪些会被拦截，确认后再提交。
- 作为作者，我想按章节区间把章节发到正确的分卷，缺的卷自动新建。

## 3. 范围

### 3.1 包含
- 认证获取：一键获取（专用 Chrome + CDP）、从技能 `.env.local` 导入、手动填写（REQ-07 原有）。
- 发布设置：AI 标记 `use_ai`、每日新发字数上限（平台级）。
- 分卷规则（每本书、每个平台）。
- 发布计划（只读）与发布执行（新发 / 覆盖）。

### 3.2 不包含
- 定时发布（`timer_status=1`）：接口支持，暂不提供入口。
- 稿件「定稿」状态跟踪：确认框提醒用户自行确认。
- 起点等其他平台的发布。

## 4. 业务规则与口径

### 4.1 需要录入的信息（与技能对照）

| 信息 | 技能来源 | Novel Hub 存储 |
|---|---|---|
| `Cookie`、`X-Secsdk-Csrf-Token` | `.env.local` 的 `TOMATO_COOKIE` / `TOMATO_CSRF_TOKEN` | `platform.cookie` / `csrf_token` |
| 书号 `book_id` | `TOMATO_BOOK_ID` | `novel_platform.book_id`（从作品链接解析） |
| 平台章节 ID `item_id` | 进度表「平台章节ID」列 | `publication.platform_item_id`（同步或发布时写入） |
| 分卷区间与卷名 | `pipeline.py` 的 `VOL_RANGES` | `novel_platform.volumes`（JSON） |
| `use_ai` | `AI_USED`（现为 2） | `platform.use_ai`（默认 2） |
| 每日上限 | `DAILY_CAP`（约 2 万字） | `platform.daily_word_limit`（默认 20000） |
| 今日已新发字数 | 平台 `create_time` 统计 | `publication.submitted_at` + `quota_words` |

### 4.2 业务规则
1. 有 `item_id` 的章节用同一 `item_id` 覆盖（回到审核中）；没有的先 `new_article` 建草稿再发布。
2. 只列状态为「未发布 / 需更新」的章节；必须显式勾选并二次确认，不做隐式批量。
3. 以下情况跳过且不提交：审核中（`display_status=5`）；有 `item_id` 但平台找不到；H1 章号与文件序号不一致；正文为空；文件丢失或不是 UTF-8；目标分卷无法确定或无法创建。
4. 分卷：未配置规则时，平台只有一卷则用它，否则要求配置规则。卷名先精确匹配，再按「：」前的主干匹配（`第一卷` 匹配 `第一卷：崩塌`）。缺卷时先 `add_volume`；返回 `-4054`（已有空卷）则跳过该章。
5. 额度：只有新发计入；新发前若「今日已新发 + 本章字数」超过上限则顺延并停止；平台返回 `-1019` 同样顺延并停止。
6. 任一章接口出错即停止，其后的章节不提交；已提交的章节逐章落库，中断不丢状态。
7. 每章提交间隔 3 秒。
8. 提交后本地记为「已发布」（`published_hash` 为发布形态 hash）；平台审核结果以下次「重新扫描」同步为准。
9. 认证原文不回传浏览器、不出现在报错文案中；一键获取用独立 Chrome 用户目录 `data/chrome-profile/`（已加入 `.gitignore`），不读取日常 Chrome 的数据。

## 5. 功能需求

### 5.1 认证获取
| 编号 | 描述 |
|---|---|
| F8.1 | 设置页番茄「配置 / 更新」中提供「一键获取（推荐）」：启动专用 Chrome（远程调试端口 9223）打开作家后台；用户登录后，读取页面发出的第一条同时带 `Cookie` 与 `X-Secsdk-Csrf-Token` 的请求头，校验通过后保存并关闭该窗口。 |
| F8.2 | 一键获取期间每 2 秒轮询进度；窗口被关闭、连接中断或 5 分钟未登录时显示错误。 |
| F8.3 | 「从文件导入」：填写技能 `.env.local` 路径，解析 `TOMATO_COOKIE` / `TOMATO_CSRF_TOKEN`（规则同 `pipeline.py` 的 `load_env`），校验通过后保存。 |
| F8.4 | Chrome 路径与用户目录可用环境变量 `NOVEL_HUB_CHROME`、`NOVEL_HUB_CHROME_PROFILE` 覆盖。 |

### 5.2 发布设置与分卷
| 编号 | 描述 |
|---|---|
| F8.5 | 设置页番茄「发布设置」：`use_ai` 只能选 1 或 2（覆盖时传 0 不生效）；每日上限 1000–200000 的整数。 |
| F8.6 | 小说详情页「管理平台」番茄行提供分卷规则编辑：每行 `起始章-结束章 卷名`，区间不得重叠；清空即删除规则。 |

### 5.3 发布
| 编号 | 描述 |
|---|---|
| F8.7 | 番茄「已配置」时，详情页显示「发布到番茄」面板；「查看发布计划」只读，列出章节、状态、方式（新发 / 覆盖）、字数、分卷（含「将新建」）与阻塞原因，以及今日已新发 / 上限、`use_ai`。 |
| F8.8 | 阻塞章节不可勾选；勾选后「发布选中的 N 章」进入确认，确认框说明覆盖章数（读者可见、回到审核中）与新发字数。 |
| F8.9 | 执行后逐章显示结果：已提交 / 已跳过 / 失败 / 已顺延，并附原因。 |
