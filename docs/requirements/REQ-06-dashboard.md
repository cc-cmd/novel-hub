## 1. 背景与目标

作者同时写多本书、发多个平台。需要一个入口页，快速回答："我有哪些书？每本多少字？每个平台发到哪了？哪些章要更新？"

**目标**：首页以卡片展示每本未归档小说的总章数、总字数，以及各已绑定平台的"已发 / 需更新 / 未发"计数，并提供添加目录与重新扫描入口。

## 2. 用户故事

- 作为作者，我打开平台第一眼就想知道各书进度。
- 作为作者，我想立刻看出哪本书有章节需要更新到平台。
- 作为作者，我想从卡片直接进入某本书的详情。
- 作为作者，我新增了小说文件夹后，想在首页一键扫描。

## 3. 范围

### 3.1 包含
- 小说卡片列表及统计
- 顶部操作："添加小说目录""重新扫描"
- 已归档显示开关
- 空状态与异常提示

### 3.2 不包含
- 平台线上数据（阅读量、收益）
- 图表 / 趋势 / 日更统计（后续）
- 搜索与排序的复杂配置（MVP 提供简单排序，见 Q1）

## 4. 业务规则与口径

### 4.1 统计口径

对每本未归档小说 N，其已绑定平台集合 P(N)：

| 指标 | 定义 |
|---|---|
| 总章数 | `chapter` 数，**含** `file_missing` 章节（见 Q2）；列表另标注"丢失 K 章" |
| 总字数 | 所有 `file_missing = false` 章节的 `word_count` 之和 |
| 某平台 · 已发 | 章节在该平台 `published` 且 `published_hash = content_hash` |
| 某平台 · 审核中 | `pending_review` 且 `published_hash = content_hash` |
| 某平台 · 需更新 | `pending_review` 或 `published`，且 `published_hash ≠ content_hash`（同 REQ-04 判定函数） |
| 某平台 · 未发 | 其余章节 = 总章数 − 已发 − 审核中 − 需更新 − 丢失章数 |
| 文件丢失 | 单独计数，不计入已发/审核中/需更新/未发 |

**恒等关系**（用于自测）：对每个平台，`已发 + 审核中 + 需更新 + 未发 + 文件丢失 = 总章数`。

仅统计**已绑定**平台；未绑定平台的发布记录不计入（REQ-03 业务规则 5）。

### 4.2 业务规则

1. 看板只读展示 + 少量入口操作，不直接修改发布状态（在详情页操作）。
2. 统计口径与详情页严格一致（共用同一判定函数，不重复实现）。
3. 归档小说默认不计入任何看板统计与扫描同步。
4. 每次进入页面都会同步，保证数据新鲜；同步失败不阻塞页面，展示上次入库的数据 + 警告。

## 5. 功能需求

| 编号 | 需求 |
|---|---|
| F6.1 | 路由 `/`。页面加载时触发一次扫描同步（REQ-01 F1.8），同步完成后渲染统计；同步期间显示骨架屏/加载态。 |
| F6.2 | 每本未归档小说一张卡片：小说名、总章数、总字数、（若有）丢失章数。 |
| F6.3 | 卡片内按平台分行：平台名 + "已发 X · 审核中 W · 需更新 Y · 未发 Z"。无绑定平台时显示"未绑定平台"并给出"去绑定"链接。 |
| F6.4 | "需更新"数 > 0 时，该项橙色加粗，卡片右上角显示徽标"↻ 需更新 N"（N 为去重后的章数，见 Q5）。 |
| F6.5 | 点击书名进入 `/novels/[id]`。点击某平台行的"需更新 Y"进入详情页并预置 `?filter=stale&platform=…`；点击"未发 Z"同理 `?filter=unpublished`。 |
| F6.6 | 顶部"添加小说目录"：在页内展开面板输入路径，行为同 REQ-01 F1.1，成功后自动扫描并刷新。 |
| F6.7 | 顶部"重新扫描"：重新执行扫描与同步，完成后提示条："新增 X 本、更新 Y 章、Z 个文件无法识别"；扫描中按钮禁用并显示进度。 |
| F6.8 | "显示已归档"开关：开启后已归档小说以弱化样式展示在末尾，卡片提供"取消归档"。默认关闭。 |
| F6.9 | 目录丢失 / 不可访问的小说，卡片显示警示标签，统计基于库中已有记录。 |
| F6.10 | 空状态：尚未配置根目录 → 引导"添加小说目录"；已配置但无小说 → 提示"未发现小说，请确认目录结构：根目录下每个子目录为一本书"。 |
| F6.11 | 卡片菜单（⋯）：重新扫描此书、设置章节目录（跳转详情页，REQ-01 F1.11）、归档 / 取消归档。 |
| F6.12 | 统计由数据库聚合查询完成，避免 N+1；100 本书 × 1000 章的规模下首屏渲染应 < 2 秒（不含首次全量同步）。 |
| F6.13 | 排序：默认按"最近修改章节时间"降序；提供按名称、需更新数排序的切换（见 Q1）。 |

## 6. 页面与交互

原型：总览看板、空状态与错误状态（见 [README「UX 基准」](README.md)）。

- **页头**：标题"我的小说"、"N 本小说 · M 个根目录"；工具栏依次为"显示已归档"开关、排序下拉（最近更新/名称/需更新数）、"重新扫描"、"添加小说目录"。
- **卡片**：书名（衬线）、"N 章 · N 字 · 丢失 K 章"、右上角需更新徽标与 ⋯ 菜单、状态标签（REQ-01 §6）。
- **平台行**：五色比例条（已发/审核中/需更新/未发/丢失）+ 文字计数；"需更新""未发"是链接（F6.5），丢失 > 0 时才显示"丢失 K"。
- **未绑定平台**：显示"未绑定平台。去绑定"，不显示 0 计数。
- **反馈**：扫描完成等结果用页内提示条；根目录不可访问时显示警告条，列出路径和原因，附"前往设置处理"。
- **同步中**：卡片骨架屏；"重新扫描"显示"扫描中…"并禁用。单卡失败显示"统计失败"+"点击重试"。
- **空状态**：无根目录时标题"先告诉我你的小说放在哪"+"添加小说目录"；有根目录无小说时标题"未发现小说"+ F6.10 文案。
- **响应式**：卡片按最小宽度 400px 自动分列，窄屏单列。
- 数字使用等宽字体对齐；状态颜色同时配文字，不单靠颜色。

## 7. 数据

不新增表或字段，仅读取 `chapter` 等已有数据。

## 8. 异常场景

| 场景 | 期望行为 |
|---|---|
| 同步失败（目录不可访问） | 页面展示已有数据 + 顶部警告条；失败的根目录列出原因 |
| 单本小说统计失败 | 该卡片显示"统计失败，点击重试"，不影响其他卡片 |
| 无任何小说 | 空状态引导 |
| 重新扫描进行中再次点击 | 按钮禁用，防止重复触发 |
| 扫描期间发布状态被修改 | 以数据库最终状态为准，完成后刷新 |

## 9. 验收标准

- **AC6.1** **Given** 2 本书、已扫描，**Then** 首页显示 2 张卡片，章数与字数与详情页一致。
- **AC6.2** **Given** 某书绑定番茄、起点，**Then** 卡片有两行平台统计；每行满足 `已发+审核中+需更新+未发+丢失 = 总章数`。
- **AC6.3** **Given** 某章在番茄已发后被修改并重新扫描，**Then** 该书番茄"需更新"+1，"已发"−1，卡片出现高亮。
- **AC6.4** **Given** 点击"需更新 3"，**Then** 跳转详情页，已应用需更新筛选，显示 3 章。
- **AC6.5** **Given** 未绑定平台的小说，**Then** 卡片显示"未绑定平台"，不显示 0 计数。
- **AC6.6** **Given** 点击"重新扫描"，**Then** 按钮扫描期间禁用，完成后提示条 汇总新增/更新/未识别数量。
- **AC6.7** **Given** 归档一本书，**Then** 默认视图消失；开启"显示已归档"可见且可取消归档。
- **AC6.8** **Given** 某本书章节文件丢失 1 章，**Then** 总字数不含该章，卡片显示"丢失 1 章"，平台计数恒等式成立。
- **AC6.9** **Given** 未配置任何根目录，**Then** 显示"添加小说目录"引导。
- **AC6.10** **Given** 根目录不可访问，**Then** 页面不崩溃，展示已有数据与警告。

## 10. 测试建议

- 单元：统计聚合函数（已发/审核中/需更新/未发/丢失 恒等式）、各边界（0 章、全未发、全丢失、未绑定平台）。
- 手动：§9 全部场景；规模测试（模拟 20 本 × 500 章）。

## 11. 待确认问题

| # | 问题 | 当前假设 |
|---|---|---|
| Q1 | 排序方式 | 默认最近更新；可切名称 / 需更新数。设计文档未规定，属补充。 |
| Q2 | 总章数是否包含丢失章节 | 包含，并另标丢失数；总字数不含丢失章节（无可靠字数）。 |
